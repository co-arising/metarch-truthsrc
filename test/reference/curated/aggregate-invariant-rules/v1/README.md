# aggregate-invariant-rules — curated golden v1 (family #45)

**Provenance: `classic-reproduction`** (ruling 2026-11-23,
`docs/emitter-unification-host-family-rulings.md` R1–R5).

This golden tree is the bank-wealth rules cluster's classic production bytes
pinned as the **reproduction receipt** — not a handwritten style spec. The
family's acceptance is byte equality with these nine files:

- `app/example/bankwealth/domain/invariant/{CreditBalance,FundOrder,SipPlan}Rules.scala`
  — the core guard-chain invariant rules (one method per command, one
  `if (!(…)) return …` line per guard, closing in the CommandHelpers emission).
- `app/example/bankwealth/domain/invariant/params/{…}RuleParams.scala`
  — the per-command params records.
- `app/example/bankwealth/domain/{…}Rules.scala` — the domain facade wrappers.

The `technical-input.json` contract (`truthsrc.aggregate-invariant-rules-input/v1`)
is the derived form of the same knowledge the classic `renderInvariant`
interpreted; every guard expression, name and file location in the golden bytes
is contract data — the emitter module embeds zero business bytes. The
`codeMappings` provenance (per-command scopes, per-guard spans) reproduces the
classic byte spans exactly; the independent cross-check lives in
`test/fixtures/aggregate-invariant-rules-v1/anchor-span-receipt.json`
(393 anchor-verified spans from the bank's classic-era anchors).

Deliberate deviations from the handwritten-golden conventions (both recorded
rulings, not oversights):

1. The files keep the classic `// @generated by truthsrc scala-cqrs-domain:1`
   header — byte continuity with the pinned receipt is the acceptance target
   (R4); removing headers app-wide is a separate user decision.
2. Cluster shape evolution (e.g. the stockreservation formal guard-object
   machine of reference family #11) belongs to the Phase 4 `all31Closed`
   evaluation, decided by the user — this family's scope is the pure producer
   retirement of the classic rules trio (R1).
