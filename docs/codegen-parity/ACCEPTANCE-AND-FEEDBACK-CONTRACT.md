记录：2026-11-16。状态：**用户已要求以下验收顺序；本文件完成合同收紧，不表示门控已实现、已运行或通过。** 本轮仍为docs-only，不增加生成器修改、生成/编译/测试/服务、消费迁移或发布授权。

## 1. 最新要求与优先关系

用户原话：

> 确定这次你在推进代码生成器编写的过程中，有靠谱的反馈环，有符合我要求的验收标准，包括不限于生成的代码至少与scala生成器生成的版本逐字节一致，下一步再考虑符合plain fp 要求的scalacheck style对生成的代码质量门控，等等

执行顺序是：**同输入准入 → 传统Scala真实生成物与JS真实生成物严格逐字节一致 → 既有明确目标与后续Plain FP/性质/静态质量门 → 实际消费闭包验收。** 不用新增文档量或测试数代替任何一门。

本合同是[fixture合同](FIXTURE-AND-EXPECTED-CONTRACT.md)、[编制合同](AUTHORING-CONTRACT.md)及已保存diff/target提案的**新增验收约束**。历史资料及源指纹不重写：其中“有限差异白名单”“允许换行/头部差异”“approved-target”等说法，均不能作为本合同RAW-BYTE门的放行依据。原资料的来源、变体、所有权、业务与运行边界继续有效。

- 唯一传统基准：固定版本及实际源字节的`CodegenMain → CQRSApplicationGenerator.runCommon → Builder/Model/Template → writer`。`template/products/*`不是替代基准。
- raw Scala、curated人工参考、approved-target、actual JS是四种不同资产；人工参考和手写目标不能冒充Scala真实生成结果。
- 已要求的三层布局、typed replyTo、Deposit Helper两臂等不撤销。若与raw有差异，先完整暴露两者，再分阶段、分候选验收；不要求一份有差异的文件同时被标成“逐字节相同”。
- 分阶段是证据和交付顺序，**不自动要求增加永久raw兼容profile、第二套编译器或大型审计框架**。架构与实际写范围仍按批准工作包决定。

## 2. 三类结论必须分开

| 结论 | PASS所需证据 | 不能替代它的东西 |
|---|---|---|
| INPUT-ADMISSION | 同一来源输入无损映射到双端，所有适用字段/默认表达/顺序/nominal/技术绑定/实现槽有明确去向；工具链与源身份固定 | 名称相同、散文大意相同、adapter静默补字段/删字段 |
| RAW-BYTE | 实际公开入口生成；预先确定范围内相对路径集合完全一致、每个完整文件原始字节完全一致；确定性及比较器负对照均有证据 | approved-target相似、AST相等、编译绿、格式化后相等、只比较交集 |
| USER-TARGET / QUALITY / RUNTIME | 在RAW-BYTE基础阶段后，分别满足已裁目标、Plain FP静态与性质合同、实际公开接口观察 | 沿用旧候选的RAW-BYTE PASS、只跑性质测试、只看页面或旧银行回执 |

每一结论必须绑定候选源/输入/输出SHA、fixture、variant、entrypoint及依赖身份。后续产物变化不能继承先前字节PASS；获批的目标演进保留raw→target完整diff，报告它确实偏离raw。raw含`???`或错误回复时可以如实证明复刻了这些字节，**但不能因此宣布代码可用、满足用户目标或适合银行消费**。

当前：INPUT-ADMISSION未闭合；RAW-BYTE没有本轮实际执行证据；F1四件目标`expectedSha`仍为`null`；性质工具/版本未选；复杂度未测。两位只读代理已独立质疑字节门及后续性质门；这是合同复核，不是门控实现或运行证据。

## 3. G0：先固定输入与独立基准

1. 保存Scala/JS的commit及实际相关源字节、真实入口与选项、fixture来源与技术绑定、adapter版本、工具/依赖版本及制品指纹。不得只用HEAD替代未提交源码身份；不得读取秘密或旧进程args/env。
2. 双端映射逐槽核对：类型/字段/顺序/缺省表达式/只读标志/回复/事件/状态/算法槽/nominal/PB/PID等。未知或无法表达的必需语义为BLOCKED；不得根据散文、curated或模板默认值补成“同输入”。
3. F1严格复刻先服从已锁定raw metadata；原raw没有默认表达式不等于补`None`，curated额外回复/Map.empty/时钟/业务实现不能进入raw。原有target候选保留到后续，不为raw复刻重新裁定已经由raw给定的事实。
4. raw expected只能由固定传统公开生成入口在获准窗口实际产生，保存完整文件和运行回执。模板源码快照、手工拼接结果、JS产物拷贝都不够。传统端无法产出则BLOCKED，不人工补造expected。
5. raw生成代码原有缺陷单列，不洗掉`???`、错位参数或writer缺陷。生成成功不等于生成代码可编译；生成命令失败也不能用残留文件算成功。
6. 预先声明本批fixture×variant×完整文件闭包及expected-present/expected-absent，不从JS实际输出反推应测集合。覆盖范围由[覆盖矩阵](fixtures/COVERAGE-MATRIX.md)导航，不用“42份文档”或“F1/F2名称”作已覆盖证据。
7. common消费遵守[正式交接约束](COMMON-CORE-CONSUMPTION-HANDOFF.md)：已发布最新版本优先，实施前锁实际制品/API与同FQN唯一供给。下一版仍是用户转述未完成，不拼接0.2、scaffold与未来API。供给变化重核受影响闭包，不暗改raw身份。

## 4. G1：严格字节门的判定规则

### 4.1 必须是实际生成产物

- Scala与JS分别走获准、明确system/target的公开CLI；JS必须包括当前被真实消费者选择的入口，而非只修一个未接线renderer。不得用内部import-and-call、模板单元返回值或手写输出替代。
- 两端在各自独占的新目录生成；运行前说明全部输出、缓存、数据库/ledger/anchor及其他旁路写面。新target本身不等于无其他副作用；不写共享应用或现有`.truthsrc/`、journal与回执。
- 固定正常运行环境中影响输出的输入，双端各重复生成一次。时间/随机/排序/平台差异必须在来源和生成端解决；若固定基准无法稳定输出，明确阻断并请求处理，不在比较时清洗。

### 4.2 精确判定

只去掉各自独占输出根得到相对路径；不得改变路径大小写、文件名或文件内容。对预先声明的完整比较范围，要求：

```text
expectedRelativePaths == actualRelativePaths
对每个path：rawScalaBytes(path) == actualJsBytes(path)
```

- 完整文件按二进制逐字节比较，SHA-256用于溯源，首个不同字节偏移和完整diff用于诊断。路径、package、import顺序、注释、空格、缩进、换行、BOM、末尾换行、MANUAL标记及完整方法体均在检查内。
- **字节差异白名单为空。** 不允许忽略生成头、统一CRLF/LF、trim、压缩空白、formatter后比较、删包/注释、AST比较替代、只比签名或片段。需要升级基准时另立版本并重新取证，不自动更新expected。
- 缺文件、额外文件、旧残留、重复路径或任一字节不同均失败。范围不能缩成两边交集；重复路径即使最终writer覆盖成一个文件也应在plan/manifest层暴露。
- 生成代码文件内的A/B混合construct不能切片后把剩余内容排除。必须先固定完整文件组装合同；未能建立同输入完整对应则该项BLOCKED。
- 没有Scala对应的B输出不冒充RAW-BYTE PASS，单列独立完整expected/质量/运行义务。JS特有证据JSON与代码文件分账，范围在生成前登记，不能在看到diff后临时排除文件。
- 四个missing classic Trigger以及未覆盖变体继续保留在总表。单批只测F1时仅能报告F1闭包结论，不能说42族全通过。真实suppressed分支要求观察“不产出”，但零文件不能被计作非空产物的字节PASS。

### 4.3 比较器本身要有反证

未来获准执行时，仅在**隔离的比较器输入副本**做以下负对照；不修改金样、实际交付生成目录或生产Scala，也不把变异副本当真实CLI产物：

| 负对照 | 必须观察到 |
|---|---|
| 改一个空格/头部字节/末尾换行，或交换import顺序 | 字节门失败并指出文件与差异 |
| 删除一个应有文件、添加一个额外文件 | 文件集合门失败，不只比较交集 |
| 把raw的`???`“修好” | raw字节门仍失败，不能因更正确而放行 |
| 换入curated文件或过期输入/依赖的输出 | 来源/身份门拒绝，不偷换oracle |
| adapter遇到无法表达的必需字段/能力 | 准入明确拒绝或BLOCKED，不吞字段或假默认 |

另取未被实施者硬编码的有效输入变体，例如标识符/有意义的字段顺序/类型组合，经双端无损准入后重生成。改变必须符合输入合同，不能发明业务规则。生成器运行时不读取expected；不接受把整份expected文本注入模型的捷径，Scala已有命名源码槽的例外仍限原范围。

## 5. 每个获准工作包的闭环

```text
锁输入与传统基准 → 现有JS公开入口暴露差异（红）
→ 定位到输入/Model/Builder/Template/组装或接线owner
→ 只修批准的生成器源码 → 同入口重新生成
→ 完整字节对账 + 稳定性 + 负对照
→ 独立审阅实际diff和回执 → 冻结本候选结论
```

- 先有可重复的失败或明确BLOCKED，再修根因；不能只给实施agent一段“理想Scala”让其写死fixture。
- diff回到具体输入槽、文件、construct/RHS与owner；不手改生成物，不通过改金样、删校验或扩大白名单消灭红灯。
- 基准保管/更新与实现写集合分离；实施代理不得自行更新expected。主agent负责共享接缝和最终集成，独立代理尝试推翻“通过”结论；不重做无关全仓调查。
- 一批只验证受影响闭包，JVM工作集中，继承既有时间/资源限制；不每个模板重跑银行，不创造另一套大型监督引擎。超时/构建阻断保留失败记录，不延长原deadline洗绿。
- 交回最小可复核证据：输入及映射身份、两端命令/退出码/日志、工具链和common供给、完整文件清单与hash、二进制结果和diff、重复生成结果、负对照、已触发/未触发变体、具体阻断、owner及下一步。
- 结论按门与候选独立记录；缺证据记NOT-RUN/BLOCKED，实际不一致记FAIL，范围外记NOT-APPLICABLE。任何应验项缺失不能给整批PASS；不报含糊“部分通过”掩盖未满足要求。

以上是要落实的反馈环，不声称已有可运行的严格门CLI。落实时先选择/复用能满足这些条件的现有机制，再给出确切执行命令；当前不发明命令名称或报告虚构运行时长。

## 6. G2：随后加入Plain FP与ScalaCheck式质量门

**性质测试不是风格检查器，也不是实际接口验收的替身。** 以下仅固化分工和反作弊要求，尚未选择工具/版本或启动测试。

| 门 | 验证对象与要求 |
|---|---|
| 静态结构/风格/依赖 | 业务根三层；Model/Builder/Template职责；纯领域无隐式I/O/时钟/全局可变配置；命名/import/ADT边界；消除无意义nextN、双重否定和重复后缀；按固定工具逐方法测CC与嵌套，不靠regex估分或String/Any表刷分 |
| ScalaCheck式性质 | 在明确前提下检验纯决定/有序fold、输入不被修改、结果确定性、类型/数值/codec合同；只能使用已裁业务性质，不自行添加余额守恒或所有命令幂等律 |
| 类型与持久化身份 | nominal隔离、PB字段号、PID、manifest、serializer、allowlist按合同；类型负例和静态检查分账，不能只靠随机往返 |
| 真实接口观察 | 真实生成产物的公开入口/应用接线执行到改变处，观察持久化、回复、发布及必要恢复；性质测试绿、编译绿不替代这份运行证据 |

### 6.1 性质必须约束实际生成代码

以后获准运行时走`真实JS CLI → 新目录中的实际Scala/PB → 编译所需闭包 → 执行生成产物`。测试框架调用编译后的产物不是生成器内部函数，但仍单列为性质测试证据，不冒称应用端到端运行。手写实现槽独立计账；未完成槽不能补写后冒称生成器已实现业务。

- 正常`Left`：失败回复，不persist、不publish；`Right(Nil)`可能是明确成功，不误作失败，也不由此推导业务幂等律。
- 非空成功：按顺序持久化并应用事件，成功回复读新State。用能实际改变State的样本抓住“回复读旧State”；只测空事件会虚假PASS。
- `toParam`、rule、回复工厂异常与持久化失败分别观察；异常不自动等于业务Left。成功回复工厂抛错时可能已经持久化，不编造回滚。
- `replyWith`与带publish变体分开；不意外发布、不把EventStream当耐久outbox。具体post/persist/publish/reply及异常顺序，以实际锁定common制品的合同为准，不提前推断下一版withPost语义。
- 金额精度、舍入、溢出只按既定类型与独立金融oracle；不把addExact改`+`。codec往返只在已确认无损域内成立，还需独立历史wire样本和非法输入；双端共同出错也可能往返成功。

### 6.2 防止随机检查自证

固定回归seed并记录探索seed；保存完整失败样本和保持前提的最小shrink反例。记录样本分布/已覆盖分支、discard与跳过原因；零有效样本、全discard、仅Nil或未触发关键分支均不能PASS。oracle不复用被测生成器/模板/业务实现；必要时采用独立模型、人工已认可样例及历史wire bytes相互制约。隔离的故障样本应证明漏事件、读旧State、非法发布等会被门抓住。
